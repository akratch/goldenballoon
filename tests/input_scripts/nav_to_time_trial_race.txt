# DKR: TITLE -> in-race, Tracks (Time Trial) mode, first Dino Domain track.
# Route (verified via MDKR_TRACE=1 menu_init + level_load):
#   TITLE(0) --2 taps--> CHARACTER_SELECT(3) --A,A--> CAUTION(28) --A-->
#   GAME_SELECT(19) --DOWN,A--> TRACK_SELECT(15) --A(world),A(vehicle),
#   A(TT off),A(GO)--> level_load(levelId=5, numPlayers=0)  [the real race]
#
# Menu input is EDGE-detected: distinct taps need a release gap; the title needs
# TWO taps (reveal menu, then select). Frames are approximate (input-ignore
# windows + fade transitions), spaced generously so each edge lands.
#
# Native input publication commits a script row authored for simulation ticket
# N immediately before the N sample.  The host counter has already advanced at
# that boundary, so literal script rows carry the same one-ticket lead as
# tools/dkr_oracle_route.py: an authored edge at N is written here at N-1.
# Durations remain authored durations.  This keeps the long-standing route
# phase exact while allowing platform_input_commit_tick() to publish completed
# tickets without a hidden one-frame input delay.
#
# Assert with: MDKR_TRACE=1 ... | grep -E 'menu_init|level_load'
#   -> menu_init 3, 28, 19, 15 then "level_load: levelId=5 numPlayers=0" (in-race).
#
# TWO consumers, and the second is why this file has no driving inputs:
#   tests/check_nav_fixtures.py   -- 2900 frames, asserts the race level loads.
#   tests/check_race_drive.py     -- 7500 frames with MDKR_AUTOPILOT=1, which
#     drives the race with DKR's own AI. This route is exactly
#     race_drive_long.txt's navigation with that file's throttle+LEFT-pulse train
#     removed; the pulse train was a blind open-loop line and re-stranded the kart
#     every time the simulation changed. See tests/README.md, "Open loop vs
#     closed loop".
